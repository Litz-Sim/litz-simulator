# Part art

Each file is the art for one catalog part: `<type>.svg`, with `--<variant>` for a
state or attribute value. The file's `viewBox` is its placement — the art draws
at those local units, and the part's pins must fall inside it (checked by
`art.spec.ts`).

## Fritzing assets

Some files are breadboard views taken from [Fritzing](https://fritzing.org)
(`fritzing-parts`), redrawn into this project's units (0.1 inch = 20 units) and
positioned so each catalog pin sits on the matching Fritzing connector. Those
files, and the one SVG they wrap, are licensed CC BY-SA 3.0 by the Fritzing
project — see `LICENSE.txt` in the `fritzing-parts` repository. Keeping them in
this project does not change the license of the rest of the simulator.

Generated by `build/fritzing/tools/convert.py`; the matching pin coordinates
land in `src/lib/parts/fritzing-geometry.ts`. Files without an entry there are
hand-drawn.

## Live art

Displays and controls that show a running value — LCD, OLED, e-paper, Nokia,
7-segment, potentiometers — are drawn by hand around `data-overlay` markers
(see `overlays.ts`). Each marker is the patch of screen, digit, knob or slider
the engine paints at runtime. These parts are never taken from Fritzing: a
static part photo would freeze the value. `art.spec.ts` fails if one of them
loses its marker, and the converter skips the same list.
